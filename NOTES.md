- Написал первые unit-тесты на pytest.
- Создал генератор синтетического дерева исследований, сессий и файлов.
- Использовал локальный `random.Random(seed)`, чтобы одинаковый `seed` давал

- Оставил ноль допустимой границей для количества сессий и файлов.

  каталоге, читается через `Path.read_text` и не оставляет файл в репозитории.
- Разделил сторонние пакеты на runtime- и development-зависимости:
  `requirements.txt` предназначен для production, а `requirements-dev.txt`

- Обновил README: отдельно описал установку production- и development-наборов
  зависимостей командами `python -m pip`.

### Ошибки и разбор

- Сначала передавал в один тест сразу несколько неправильных аргументов. Из-за
  этого срабатывал первый guard, и тест не доказывал ошибку нужного параметра.
  Исправил тесты по правилу «один тест — одна изменяемая причина».
- Использовал одно общее сообщение `ValueError`, но `pytest.raises(...,
  match=...)` ожидал имя конкретного параметра. Сделал сообщения точными.
- Обернул всю функцию в большой положительный `if/else`. После появления guard
  clauses этот блок стал недостижимым по ветке `else`; удалил лишнюю
  вложенность и оставил основной путь функции линейным.
- В одном граничном тесте одновременно проверял пустой список сессий и наличие
  одной сессии. Разделил это на два сценария: ноль сессий и одна сессия без
  файлов.
- Несколько раз столкнулся с несохранённым буфером IDE: Python и pytest читали
  старую версию файла с диска. Закрепил правило проверять сохранение перед
  запуском.
- При настройке теста уникальности сначала передал число всех ожидаемых файлов
  как `files_per_session`. Из-за вложенного цикла генератор создал 48 файлов
  вместо 12. Исправил аргумент на три файла для каждой из четырёх сессий.
- Первая версия файлового теста проходила, хотя отчёт не содержал размер файла:
  в тесте не было соответствующей проверки. Добавил `Size` в формат отчёта и
  явное утверждение о нём.
- Сначала повторно обернул fixture `tmp_path` в `Path` и вызвал instance-метод
  как `Path.read_text(path, ...)`. Убрал лишнее создание объекта и перешёл к
  обычному вызову `path.read_text(...)`.
- В первой версии `requirements-dev.txt` допустил опечатку `reqirements.txt`.
  pip попытался буквально открыть файл с таким именем и завершился ошибкой
  `No such file or directory`. Исправил имя на `requirements.txt`.
- При push обнаружил истёкший токен GitHub CLI и расхождение локальной и
  удалённой веток. Повторно авторизовался штатным браузерным способом, выполнил
  rebase, разрешил конфликт и отправил изменения обычным fast-forward push без
  `--force`.

### Проверенный результат

- Полный набор из 11 тестов проходит.
- `ruff check` не находит ошибок.
- `ruff format --check` подтверждает форматирование.
- `pip check` не находит отсутствующих или несовместимых зависимостей.
- `git diff --check` не находит проблем с пробелами и окончаниями строк.

### Что я понял

- Аннотация типа не проверяет диапазон значения во время выполнения.
- `ValueError` подходит для аргумента правильного типа с недопустимым значением.
- `raise` немедленно прекращает выполнение функции, поэтому порядок guard
  clauses определяет первую наблюдаемую ошибку.
- Граничное значение `0` и ошибочное значение `-1` относятся к разным классам
  эквивалентности и должны проверяться отдельно.
- `len(list)` показывает количество элементов, а `len(set(list))` — количество
  уникальных значений, потому что множество не хранит дубликаты.
- Проверка ожидаемого количества объектов не заменяет проверку уникальности их
  ID: четыре разных объекта могут получить одинаковый ID.
- Вложенный list comprehension для файлов соответствует двум вложенным циклам:
  сначала перебираются сессии, затем файлы текущей сессии.
- Объект `Path` представляет путь, но сам по себе не создаёт и не открывает
  файл; оператор `/` соединяет компоненты пути с учётом платформы.
- Режим `"w"` создаёт или полностью перезаписывает файл, а `"a"` сохраняет
  существующее содержимое и добавляет данные в конец.
- Контекстный менеджер играет роль гарантированного `fclose`: выход из блока
  `with` закрывает файловый ресурс даже при исключении.
- Зелёный тест подтверждает только реализованные утверждения, а не все
  требования: отсутствующая проверка способна скрыть дефект.
- Модули стандартной библиотеки, включая `pathlib`, поставляются с Python и не
  записываются в requirements-файлы.
- Runtime-зависимости нужны работающему приложению, а pytest, Ruff и другие
  development-инструменты не должны без необходимости попадать в production.
- `-r` в requirements-файле подключает другой файл, поэтому development-набор
  может включать весь runtime-набор без дублирования.
- Прямые зависимости выбирает проект, а транзитивные устанавливаются потому,
  что нужны прямым зависимостям.
- Успешные тесты подтверждают поведение, но не гарантируют, что код уже
  отрефакторен: структуру нужно дополнительно читать и проверять.

  результат: строковый ID не совпадёт с числовым ID.

## 2026-07-31 — Первая схема PostgreSQL

### Что я реализовал

- Установил PostgreSQL 18.4 и создал локальную базу `lab_storage`.
- Создал роль `sergey` и подключился к базе через локальный Unix-сокет без
  хранения пароля в репозитории.
- Описал в `sql/schema.sql` таблицы `studies`, `sessions` и `files`.
- Добавил 64-битные identity-ID, первичные ключи и внешние связи
  `sessions -> studies` и `files -> sessions`.
- Для обязательных полей применил `NOT NULL`, для дат —
  `timestamp with time zone` и `CURRENT_TIMESTAMP`.
- Размер файла храню в байтах как `bigint` и запрещаю отрицательное значение
  ограничением `CHECK`.

### Ошибки и разбор

- Сначала написал `CREATE_TABLE` как единый идентификатор вместо двух ключевых
  слов `CREATE TABLE`, поэтому SQL-парсер не распознал начало команды.
- Допустил опечатку `PRYMARY` вместо `PRIMARY` во всех первичных ключах.
- В первоначальном варианте пропустил `NOT NULL` у `files.created_at` и точку с
  запятой после последней команды.
- До повторного запуска проверил состояние базы: после синтаксических ошибок ни
  одна таблица не успела создаться, поэтому удаление объектов не потребовалось.

### Проверенный результат

- В базе существуют три таблицы, принадлежащие роли `sergey`.
- PostgreSQL подтвердил три первичных B-tree индекса и обе внешние связи.
- Все ID создаются как `GENERATED ALWAYS AS IDENTITY`.
- Ограничение `files_size_bytes_check` запрещает отрицательный размер.
- mypy, 11 pytest-тестов, Ruff, `pip check` и `git diff --check` проходят.

## 2026-07-31 — INSERT и SELECT связанных данных

### Что я реализовал

- Создал `sql/seed.sql` с одним синтетическим исследованием, двумя сессиями и
  тремя файлами.
- Получал автоматически созданные ID через `INSERT ... RETURNING` и сохранял
  их в переменные клиента `psql` командой `\gset`.
- Передавал ID родителей в дочерние строки, не предполагая конкретные значения
  identity-счётчиков.
- Добавил многострочный `INSERT` для трёх файлов.
- Написал `SELECT` с явным списком столбцов, `WHERE`, `IN` и `ORDER BY`.
- Выполнил весь seed-файл с `ON_ERROR_STOP` внутри одной транзакции.

### Ошибки и разбор

- Сначала поставил точку с запятой перед `RETURNING`. Она завершила `INSERT`,
  поэтому `RETURNING` стал отдельной ошибочной командой, а две сессии успели
  сохраниться при неатомарном запуске.
- Перепутал имя столбца `session_id` с переменными `session_1_id` и
  `session_2_id`: столбец указывается слева в списке `INSERT`, а переменная —
  как значение в `VALUES`.
- Использовал `ORDER BY` там, где требовалась фильтрация через `WHERE`.
- Пропустил запятую между `session_id` и `name`; без неё SQL мог интерпретировать
  `name` как псевдоним предыдущего выражения.
- При переносе shell-команды написал обратный слеш перед пробелом, а не перед
  переводом строки. В результате `psql` не распознал параметры `--dbname` и
  `--file`. Дополнительно исправил имя базы с `lab-storage` на `lab_storage`.
- Перед повторным запуском очистил только синтетические строки и сбросил
  identity-счётчики через `TRUNCATE ... RESTART IDENTITY`.

### Проверенный результат

- В `studies` находится одна строка, в `sessions` — две, в `files` — три.
- Обе сессии ссылаются на созданное исследование, а три файла — на созданные
  сессии; потерянных внешних связей нет.
- Все строки получили одно значение `created_at`, потому что
  `CURRENT_TIMESTAMP` возвращает время начала текущей транзакции.
- mypy, 11 pytest-тестов, Ruff, `pip check` и `git diff --check` проходят.
